# common-application-core

## 模块定位
`common-application-core` 是业务应用层的核心基础模块，目标是把各服务都需要的“请求处理骨架能力”集中沉淀，避免在每个业务模块重复实现。

## 主要作用
1. 统一异常处理出口
- 提供全局异常处理（`GlobalControllerHandler`），将常见异常统一转换为标准响应结构，减少控制器内重复 `try/catch`。
- 让接口错误语义和返回格式一致，便于前端与调用方稳定对接。

2. 统一租户操作约束
- 提供租户操作切面（`OperateTenantAspect`），在进入控制器前校验并设置“操作租户”上下文。
- 将多租户权限校验与上下文设置前置，降低越权风险。

3. 统一用户上下文维护约定
- 定义用户上下文维护接口（`UserContextMaintenanceService`），约束“设置/清理用户上下文”的标准流程。
- 让上下文相关逻辑具备一致实现入口，便于扩展和治理。

4. 提供应用层通用工具支撑
- 提供 Bean、请求分发、用户信息等通用工具类，减少业务代码中的重复样板。

## 已集成模块（当前项目）
1. `common-response`
- 统一响应模型与结果封装能力，用于规范接口成功/失败返回结构。

2. `common-application-context`
- 提供应用层上下文能力，支撑请求处理过程中的上下文传递与访问。

3. `common-orm-parser`
- 提供 ORM 相关解析能力，辅助应用层与数据访问相关的通用处理。

4. `common-application-model`
- 提供应用层通用模型定义，减少跨模块重复 DTO/模型声明。

5. `common-json`
- 提供统一 JSON 处理能力，保证序列化/反序列化行为一致。

6. `common-request`
- 提供请求参数与请求处理相关的公共能力，减少控制层重复代码。

7. `common-security-route`
- 提供路由安全相关能力，支撑请求访问控制与安全约束。

8. `common-system-context`
- 提供系统级上下文能力，用于维护系统维度的运行上下文信息。

## 价值总结
`common-application-core` 的核心价值不是承载业务逻辑，而是提供业务逻辑运行所依赖的统一基础能力：
- 统一：异常、租户、上下文处理方式一致。
- 安全：关键校验前置，降低权限和上下文使用风险。
- 提效：业务模块聚焦业务本身，减少重复基础代码。
- 可维护：基础能力集中演进，变更影响范围可控。
